3권에서 갑자기 구성이 바뀌지 않도록 1·2권에 2~4쪽 박스를 세 곳 넣는다. 1·2권에서는 직접 만들지 않고 **완성된 모듈을 돌려 보는 것**까지만 한다.

| 위치 | 맛보기 | 이어지는 곳 |
|---|---|---|
| 1권 8장 SSH 인증 공격 | 같은 대입 공격을 `brute_success.py`로 돌려 경보를 보고, 그 경보를 AI에게 물어 판단을 받아 봄 | 3권 1장 |
| 2권 12장 장기 로그 집계 | Dev Tools 집계를 파이썬 몇 줄로 똑같이 돌려 건수를 맞춰 봄 | 3권 0장 |
| 2권 13장 위험도 평가 | 손으로 계산한 위험 점수를 `entity_risk.py`가 자동으로 매기는 것을 봄 | 5권 1장 |

- 코드는 저장소에 완성본으로 두고, 책에는 실행 명령 2~3줄과 결과 화면만 넣는다.
- AI 부분은 경보를 붙여넣고 물어보는 수준으로만, MCP 연결 없이 한다.
- 박스마다 마지막 줄에 "3권 ○장에서 직접 만든다"를 적는다.

## 4. 3권부터 — 공격기법별 종단 구성

### 4.1 단원 5단계

모든 단원이 같은 순서로 끝까지 간다. 1·2권에서 배운 것은 다시 설명하지 않고 해당 장을 가리킨다.

1. **공격**: kt66 실습 재현(1·2권 실습 재사용), 퍼플 집계 합성 로그 주입, 공개 PCAP 재생 중 하나로 만든다. 공격 절차는 단계 설명으로만 쓴다.
2. **개념**: 공격 기법(ATT&CK)과 방어 개념. 이 공격이 로그에 무엇을 남기는지까지.
3. **분석**: Discover로 찾고 Dev Tools 집계로 정량화한다. 이 단원에서 처음 필요한 Wazuh 기능은 여기서 "기능 박스"로 한 번만 설명한다.
4. **파이썬 모듈**: 카탈로그 프로그램 1~2개를 바이브코딩으로 만든다. AI가 만든 쿼리는 Dev Tools에서 건수를 맞춘 뒤 넣고, 정상 데이터를 섞어 오탐을 잰다.
5. **AI 대응**: 모듈을 MCP 도구로 감싸 LLM이 판단하고, 대응은 안전장치가 들어간 도구와 사람 승인을 거친다. 상황에 맞으면 ML 분석도 여기서 붙인다.

공통 틀(모듈 틀, MCP 틀, 안전장치)은 3권 0장에서 한 번 만들고, 단원마다 탐지 로직과 도구 하나씩만 더한다.

**1·2권에서 이미 배운 것(참조만)**: Discover·DQL, 커스텀 디코더·룰과 wazuh-logtest, FIM, auditd, Sysmon, osquery, command 모니터링, 기본 Active Response, SCA, 취약점 탐지, VirusTotal 연동, Suricata 경보, MITRE 태그, Dev Tools 집계 기초(2권 12·13장)
